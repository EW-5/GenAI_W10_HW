為什麼 LLM 需要 RAG

  • LLM 的知識來自訓練。遇到新資訊或專門規章，回答可能過時、缺少細節，或出現看似合理的錯誤（Hallucination）。
  • 上下文視窗（Context Window）限制一次可處理的輸入量，系統需要挑選相關內容。
S01 §1 S04「Why is Retrieval-Augmented Generation important?」 S05「The challenges of RAG」

RAG 的基本概念

  • 檢索增強生成（Retrieval-Augmented Generation）讓模型在回答時使用找回的外部資料。這裡的「先查」指回答時取用資料。
  • 教學例子｜問「退選期限是什麼時候？」系統先找校內規章的相關條文，再交給模型整理答案。
S02 §II-A

一般 LLM 與 RAG 的差異

  • 未搭配檢索的 LLM｜問題 → 模型運用訓練時學到的知識 → 回答
  • RAG｜問題 → 從外部知識庫找相關資料 → 模型依問題與資料回答
S01 §1 S04「Why is Retrieval-Augmented Generation important?」 S02 §II-A

RAG 完整運作流程

  1. 建立索引（向量式流程）｜外部文件 → 視需求切分並向量化 → 可搜尋的索引
  2. 檢索（Retrieval）｜按問題搜尋索引，取回候選片段。
  3. 增強（Augmentation）｜把選出的片段和問題放進模型輸入。
  4. 生成（Generation）｜模型依據輸入撰寫回答。
  5. 維護｜外部文件有變更時，同步更新索引。
S02 §II-A S03「The integration layer」 S03「The generator」 S04「Update external data」

文件切分與向量化

  • 文件切分（Chunking）｜把長文件分成可獨立搜尋的片段。片段太短可能失去前後文，太長可能混入無關資訊。
  • 向量化（Embedding）｜用一組數值表示內容，讓系統比較相似度。教學例子中，向量搜尋可將「年度休假餘額」列為「剩幾天特休？」的可能相關片段。
S02 §III-B.1 S05「Solving query understanding challenges」 S03「The retriever」

檢索與答案生成

  • 檢索｜向量檢索可按相似度取前 k 筆（Top-k）。需要時可重新排序（Reranking），讓較相關的片段排在前面。
  • 生成｜模型讀取問題與選出的片段後撰寫答案。應用可附上來源，讓讀者回查。
S02 §§II-A、IV-A.1 S04「Enhanced user trust」 S03「The integration layer」與「The generator」

RAG 應用案例

  • 內部人資問答｜查找休假政策與使用者有權查閱的個人紀錄，再交給模型整理。
  • 客服知識助理｜查找產品說明與支援政策，再由模型整理成回覆。
S04「Retrieve relevant information」與「More developer control」 S03「Specialized chatbots and virtual assistants」

RAG 的優點與限制

  • 可追溯｜應用可附來源，讓讀者查核答案。
  • 檢索限制｜系統可能漏掉證據，也可能取回冗餘、錯誤或互相矛盾的片段。
  • 生成限制｜回答中的主張可能缺乏片段支持，需逐一確認。
  • 資料維護｜文件更新時要維護索引。
  • 存取與效能｜私人文件須限制存取，並在搜尋深度與速度之間取捨。

學習總結與參考資料

  • 先準備可搜尋的索引，再用問題找回相關片段。
  • 把挑選出的片段和問題交給模型。
  • 讀完答案，再回查哪些證據支持它。
