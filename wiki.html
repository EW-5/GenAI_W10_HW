RAG 的應用

  • 組織內部問答。例如員工詢問休假規則時，系統檢索相關政策和經授權的個人紀錄，再將結果交給模型。 S04「Retrieve relevant information」與「More developer control」
  • 客服知識助理。從產品說明及政策中尋找支援內容，由模型整理成回覆。 S03「Specialized chatbots and virtual assistants」
  • 知識密集的 NLP 任務。原始論文測試開放域問答與事實查核。綜述也列出資訊擷取和對話生成等任務。 S01 §§3.1、3.4 · S02 §VI-A

Chunking（文件切分）

Chunking 把長文件切成可獨立搜尋的片段。切分可依 token 數、句子或其他適合文件結構的邊界。切得太小容易遺失前後文，太大則可能混入無關內容並占用更多輸入空間。 S02 §III-B.1 · S03「The knowledge base」

可以保留文件名稱、頁碼與日期等 Metadata（中繼資料），以便限制搜尋範圍及回查片段位置。 S02 §III-B.2

Embedding（嵌入向量）

Embedding 是模型產生的一組數值，可用來比較內容的相似程度。例如，提問「剩幾天特休？」與條文「年度休假餘額」的字面不完全相同，向量搜尋仍可以把它們列為可能相關的內容。這是依向量檢索原理設計的教學例子。 S03「The retriever」 · S05「Solving query understanding challenges」

原始 RAG 論文使用 DPR 的查詢編碼器和文件編碼器產生向量，再以內積比較。索引中的向量用來找候選片段，之後提供給生成模型的是片段內容。 S01 §§2.2–2.3

RAG 運作流程

建立索引（Indexing）

先整理外部文件，視需求將全文切成片段，建立可搜尋的索引。向量式流程會先為每個片段建立 Embedding。 S02 §II-A · S05「Content preparation for RAG」

回答問題

  • Retrieval（檢索）。使用問題搜尋索引，取回候選片段。 S02 §II-A
  • Augmentation（增強）。選擇需要的片段，將問題和片段組成模型的輸入。 S03「The integration layer」
  • Generation（生成）。模型根據輸入撰寫回答，應用可以附上引用。 S03「The generator」 · S04「Enhanced user trust」

外部資料有變更時，索引也要反映更新。一個過期的索引仍可能把舊資料交給生成器。 S04「Update external data」

Generation（生成）

生成階段將問題與選出的片段交給 LLM，形成 Augmented Prompt（增強提示）。例如詢問退選期限時，模型可用取回的條文組織答案，應用可保留條文的連結供查核。 S03「The integration layer」與「The generator」 · S04「Enhanced user trust」

候選太多可能稀釋關鍵資訊。生成前可透過 Reranking、片段篩選或壓縮，決定哪些證據送入模型。檢查輸出時，可以分別看 Answer Relevance（回答是否切題）與 Faithfulness（回答是否忠實於提供的證據）。 S02 §§IV-A、VI-C.1

RAG 的限制

  • 檢索品質。索引可能漏掉關鍵證據，或回傳錯誤、冗餘及互相矛盾的內容。 S02 §§III-B、VII-B
  • 生成忠實性。檢索到片段後，仍需評估回答中的主張是否得到這些片段支持。 S02 §VI-C.1
  • 維護與權限。更新文件後需要同步維護索引，私人文件的檢索須依使用者權限控制，並在速度與搜尋深度間取捨。 S04「Update external data」 · S05「The challenges of RAG」

來源觀察差異

  • S02 §§IV-A、VII-B 提醒冗餘或矛盾資料可能有害，也轉述特定研究中加入無關資料意外提升準確率的結果。
  • S05「Solving token constraint challenges」 在其產品情境強調回傳少量高相關片段與限制結果數量。

LLM 的限制

大型語言模型（LLM）把訓練中學到的知識存於參數。知識會受訓練資料範圍與時間限制，回答可能過時或欠缺領域細節。模型也可能產生看似合理的錯誤內容（Hallucination），而單靠回答文字難以追溯資訊來自哪裡。 S01 §1 · S04「Why is Retrieval-Augmented Generation important?」

LLM 一次能處理的輸入有 Context Window（上下文視窗）限制。檢索系統因此需要從大量文件中挑選與問題相關的內容。 S03「The knowledge base」 · S05「The challenges of RAG」

RAG 定義

RAG（Retrieval-Augmented Generation，檢索增強生成）讓生成模型在回答時使用檢索到的外部資料。以校內規章為例，系統先找出和「退選期限」有關的條文，再讓模型根據條文回答。這是依流程設計的教學例子。 S02 §II-A · S03「How does RAG work?」

來源的用法差異

  • S01 §§1、2.4 的 RAG 是一套特定的端到端訓練架構，將預訓練生成器與 Wikipedia 段落索引結合。
  • S03「What is the difference between RAG and fine-tuning?」 以系統整合為主，說明既有模型可於推論時使用外部知識，也可搭配 Fine-tuning。

Retrieval（檢索）

Retriever 從知識庫找回與問題相關的候選。例如向量搜尋可依相似度取前 k 筆（Top-k）。初步取回的候選也可以透過 Reranking（重新排序）再按相關性排列。 S02 §§II-A、IV-A.1 · S03「The retriever」

來源的比較條件

  • S04「What is the difference between Retrieval-Augmented Generation and semantic search?」 認為只用傳統關鍵字搜尋，在知識密集任務中的效果有限。
  • S01 §4.5 Retrieval Ablations 在 FEVER 實驗裡觀察到 BM25 表現較佳，並指出該組聲明高度集中於實體名稱。論文中其他任務則是可學習的檢索器表現較好。
  • S05「Maximize relevance and recall」 在其產品情境建議 Hybrid Search（混合搜尋），合併關鍵字與向量搜尋的結果。

摘要與定位

  • S01 §1 Introduction。作者把生成模型參數中的知識和可替換的 Wikipedia 段落索引結合，讓模型在生成時使用外部資料。
  • S01 §§2.1–2.4 Methods。DPR 將查詢與段落編碼成向量，用內積找候選，BART 以輸入與取回的段落為條件生成。RAG-Sequence 在序列層級對候選文件作邊際化，RAG-Token 則在每個 token 層級作邊際化。訓練時更新查詢編碼器及生成器，固定文件編碼器與索引。
  • S01 §§4.1、4.5 Results。作者比較開放域問答表現，並在指定實驗中展示可於測試時換用不同年份的 Wikipedia 索引。
