# HTML 簡報製作流程

以現有 LLM Wiki 作為唯一知識來源。每次依 N1 至 N9 順序執行，記錄每個關卡的實際結果。關卡未通過時，依表內退回位置處理，修正後重跑受影響的節點和關卡。

```text
N1 查詢 → N2 覆蓋 → N3 證據 → N4 大綱 → N5 逐頁稿
                                              ↓
N9 交件 ← N8 瀏覽器檢查 ← N7 生成 HTML ← N6 忠實度
```

| 節點 | 作業與通過條件 | 未通過時 |
| --- | --- | --- |
| N1 查詢 Wiki | 讀取 Wiki 索引、概念和來源頁。在 sources.md 記錄查到的頁面與引文範圍。 | 重新查詢 Wiki。 |
| N2 檢查覆蓋率 | LLM 限制、RAG 定義與差異、完整流程、切分、向量化、檢索、生成、應用及利弊均有對應頁面。 | 退回 N1 補查。Wiki 本身不足時停止並回報。 |
| N3 建立證據卡 | 在 cards/ 記錄主張、Wiki 路徑、來源編號、章節與原文入口。寫大綱前先跑證據定位檢查，再逐項對照主張是否保留 Wiki 的條件、可能性及教學例子標註。 | 修正該證據卡。 |
| N4 建立大綱 | outline.md 包含 10 頁，依初學者的學習順序安排。 | 修正大綱相關頁。 |
| N5 建立逐頁稿 | drafts/ 每頁有頁碼、標題、正文及與各段對應的證據、來源與 Wiki 連結。 | 修正該頁。 |
| N6 檢查稿件 | 執行結構檢查並逐頁對照證據卡與 Wiki。另用獨立審查流程覆核忠實度。沒有獨立審查環境時，交付逐頁稿與證據供新對話審查，記錄待辦。 | 引用或敘述問題退回 N5，只修該頁。證據卡問題退回 N3。 |
| N7 生成 HTML | 使用通過 N6 的稿件建置。只調整呈現方式，標題、正文及引用文字忠實保留。 | 修正建置後重跑 N7。 |
| N8 渲染與功能 | 驗證頁數、來源、引用、Wiki 連結及 HTML 文字。環境支援時，逐頁檢查瀏覽器版面、頁碼及滑鼠和鍵盤切換。 | 版面問題退回 N7。字數問題退回 N5。環境無法執行瀏覽器時記錄缺項。 |
| N9 交件 | 更新入口、README、實際執行紀錄及反思。核對交付內容並提交 Git。 | 補齊紀錄並重新核對。 |

## Loop 規則

只有該節點檢查未通過才觸發修正。每輪只修報告列出的問題，每個節點最多修正三輪。三輪仍未通過就停止並記錄問題。Wiki 資料不足時停止，不用模型自身知識補齊。記錄失敗條件、退回節點、修正內容、重跑結果與輪次。

## 執行指令

在專案目錄執行。N3 完成證據卡後，先執行 `python scripts/validate_slides.py --cards`，逐項對照 Wiki 並記錄通過後進入 N4。完成 N5 後，執行 `python scripts/validate_slides.py --drafts`，並完成 N6 內容對照。通過後執行 `python scripts/build_slides.py`、`python scripts/validate_slides.py`。在有 Edge 與 Python websocket-client 的環境執行 `python scripts/check_slides_browser.py`。完成後更新 [實際執行紀錄與反思](report.md)。
